# 2026-10-25 — Uncommitted worktree snapshot

This is the initial internal snapshot of the feature work present in the
working tree on this date. These changes are not necessarily committed or
deployed.

## Roles and account access

- Added the Developer role to permission and membership handling, including
  Developer labels and premium/admin access behavior. Legacy Owner values are
  still accepted and displayed as Developer.
- Added Developer role coverage to the admin user UI and role-related tests.
- The feature-rollout UI and runtime behavior were removed after being
  reconsidered. A database cleanup migration removes the feature-flag table
  and rollout Realtime policies.

## Community safety and staff notifications

- Expanded community reporting and moderation workflows, including member and
  content reports, report review actions, and a ban-appeal submission path.
- Added optional Resend notifications for feedback, community reports, ban
  appeals, and business applications. Email delivery is disabled unless
  `EMAIL_NOTIFICATIONS_ENABLED=true`; saved submissions remain saved if a
  notification fails, and the UI reports that warning.
- Added setup notes for the notification environment variables and verified
  sending domain.

## Business account verification

- Business applications now collect a registration identifier and a public
  verification link.
- Admin review surfaces show the submitted verification information, while
  applicants receive clear submission and notification status.

## Brewing forms and vessel UI

- “Other” batches now have a separate optional Style or type field (for
  example, Kombucha), stored independently from the batch name and shown in
  batch recipe displays. The field is placed between Batch name and Volume in
  creation and edit forms.
- The “Other” batch edit form uses the saved Full process text field rather
  than structured process-step controls, with Full process below Additives.
- Batch edit common fields use required validation and type-specific labels
  and process guidance aligned with batch creation.
- Vessel cards on the dashboard and member profiles use a borderless card
  treatment; shared vessels retain the share icon with a subtle surface
  texture. Dashboard spacing and helper copy were also adjusted.

## Download page and desktop assets

- Redesigned the desktop download page hero with neutral styling.
- Updated application icon assets and moved the web favicon into `public`.

## Database migrations

- Added migrations for membership status, business verification fields,
  Developer role support and feature flags, rollout Realtime policies, feature
  rollout cleanup, and the `batches.other_style` field.
- Apply the migrations required by the retained features in deployment order.
  The feature-rollout creation and cleanup migrations are both present because
  the rollout implementation was later removed.
