## Developer Feature Toggles

Implemented a feature flag system for controlling access to beta/unreleased features:

### Features Controlled
- **Beer & Brewing Reviews** — A business directory and product review system
- **Business Account** — Business/brewery account management

### How It Works
- Both features are **disabled by default**; developers can access the gated pages for testing
- Developers can enable features via `/admin/feature-rollout`
- Logged-in navigation checks the toggle status
- Updates attempt to record an audit entry and report audit failures

### Implementation Details
- New `feature_toggles` table with RLS policies for security
- API endpoints for fetching and managing toggles (`/api/features`, `/api/admin/feature-toggles`)
- Route-level guards on the directory, business and product pages, management
  pages, and the business administration page
- Public and signed-in navigation, business administration links, review
  details, and registration prompts respect each toggle independently.
- Rating achievements, profile counts, and notifications are hidden from
  non-developers while reviews are disabled; developers retain preview access.
- Server toggle reads are not cached
- Feature rollout admin panel at `/admin/feature-rollout`
- Brewery APIs are not fully gated; see `FEATURE_TOGGLES.md` before relying
  on the toggles as access control.
- Apply `20261110220000_secure_feature_toggle_writes.sql` to remove direct
  client writes and restrict updates to the developer-checked API.

### Usage
1. Sign in as a developer
2. Go to `/admin/feature-rollout`
3. Click "Disabled" next to any feature to enable it
4. The saved status is reflected in logged-in navigation
